# 写作结构

以下是读者需要的信息，顺序和分节随题目调整。标题承诺多个问题时都要答；一个事实只在最有用的地方讲。

| 体裁 | 优先解决的问题 |
| --- | --- |
| 公众号分享、软件推荐 | 选一个任务、成品或实际选择，写能交付什么和适用边界。其他功能只有提供新价值才写。需要获取时给可靠入口。 |
| 知乎、百度知道 | 先回答原问题，跟上理由和适用条件。已有问题可直接给正文。没有经历时用事实与推理支撑。 |
| SEO、短下载 | 尽早回答搜索动作。下载文让读者找到正确版本、来源和必要安装步骤。问功能兼下载时也给有代表性的用途。 |
| 教程、排错 | 讲清目标、材料和前提，给必要步骤、可复制指令或排查路径，说明怎样核验结果。无法确认按钮时写操作目标。操作涉及敏感材料、执行或覆盖时保留授权与核对条件。 |
| 项目科普 | 解释产品或内容是什么、需求从哪来、合法素材、制作与分发流程。涉及变现，讲谁付钱、有效行为和成本。到流程需要工具时再介绍。批量任务保留小样和人工返修。 |
| 项目复盘 | 围绕作者给出的一次具体选择。写当时怎么做、哪里失败、为什么调整、实际结果。素材缺结果便停在已知阶段。 |
| 福利 | 先说明经核实的权益和资格，再让读者找到领取方式及到账验证。 |
| 落地页 | 读者已有兴趣，从产品用途或真实产物进入，突出获取、必要依赖、费用与限制。 |
| 热点、新闻、产品说明 | 热点交代事实与日期，写相关影响。指定新闻稿、企业说明或完整评测时按体裁保留实质背景、同条件比较和必要规格。 |

改写先确定应保留的信息、作者观点、链接和披露，先动顺序及冗余，再润句子。平台转换重排读者先需要知道的事。口播可压缩背景，将长链接或指令留给画面原样显示，成品镜头依据用户素材。局部编辑只交付指定内容。长文、详细清单及复杂流程由实际需求决定。
