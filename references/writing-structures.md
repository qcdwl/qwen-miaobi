# 写作结构：按读者需求选择，而不是套模板

下列箭头表示信息顺序，不是强制小标题。每篇选择一条主线，可合并或删减；用户给结构时优先遵守。

## V1.2 先决定规模，再决定结构

普通分享可以只有标题、若干自然段和一个下载小标题，也可以无小标题。综合功能与指定系统下载一般400–700字，通常0–2个有信息的小标题；单一下载150–400字。不是固定模板或字数考核；若题目需要完整清单、复杂教程或明确长文，按要求展开。先确定本题必要的两三件事，避免“差异解释—功能列表—适用人群—收费—风险—总结”成为默认长文。

- 功能分享：用一个场景或成品贯穿，其他功能有独立价值才补；不要再设“普通人能用来干嘛”重复同一批功能。
- 功能兼Windows下载：可先用具体办公任务引出工具，再给必要Windows入口；若下载意图更强可直接从入口开始。下载段不再推销一遍产品。
- 简短下载：用途一句＋已核实入口/系统＋必要步骤；讲完结束。
- 真实项目/成品：先讲内容是什么和读者如何做，再讲工具和边界；已经引流的落地页直接说明成品及获取。
- 纯观点：可以短到几段，无“总结”栏目。只有真正复杂的教程才需要编号步骤或表格。

移动端不是每项功能都加标题。把必要限制放在对应操作附近，合并重复信息，结尾不是必选段。

## 类型一：互联网项目分享

- 机制型：一句讲清项目 → 谁付钱、怎样算有效 → 实际流程 → 成本/规则/风险 → 适合谁。
- 复盘型：用户提供的真实结果或问题 → 原先怎么做 → 哪里卡住 → 调整原因 → 当前结果（无结果就不编）→ 下一步。
- 判断型：先表态适不适合新人 → 用具体门槛解释 → 比较可替代做法 → 给行动建议。

项目要区分佣金上限与实际到手、预估与结算、有效用户与点击。用真实资料，不把收入测算当承诺；涉及项目政策读营销与专项规则。没有收益数据也能讲清机制，不要求作者提供截图才能开写。

## 类型二：AI工具/软件推荐

- 场景型：一个难做的任务 → 工具能交付什么 → 如何用 → 获取方式 → 限制。
- 成品型：真实成品/截图 → 解释关键操作 → 下载或安装 → 读者适用性。没有成品则改成示例场景，不写假体验。
- 对比型：现有方案的问题 → 新工具具体差异 → 哪些情况适合/不适合 → 获取方式。基于同版本、同条件的可证比较，不虚构实测。

标题可写具体功能，不需要每篇都从「发现了一个软件」开头。功能选两三个与任务最有关的，其他可省。安装说明应核实项目、发行版、系统和依赖；免费源码不代表服务免费。不要默认加营销。

### 兼问功能与下载：以实际任务串联

普通读者想了解工具时，可以从个人判断、具体任务或真实成品开头，选少量重点讲它如何处理材料、产物如何核对，再自然提供下载入口和必要安装信息。也可以先答下载再介绍用途。不要把每种能力做成一个独立功能标签；企业定价、模型数、发布时间不是默认必写项。

### 项目机制与落地页的区别

项目科普可按「读者见过的内容形式 → 为什么有人需要 → 合法制作/运营流程 → 成本及有效收益机制 → 工具在其中的位置」展开；可以借真实成品作为开头。只介绍软件的落地页则直接展示成品或用途，接获取方式、必要步骤、依赖与费用；不重复讲整个行业历史。批量创作场景应交代小样测试、人工核对和关键返修环节，避免宣传无条件一键成品。上述路线不固定章节、顺序和字数。

## 类型三：SEO搜索型

- 下载型：直接回答有无、官方或第三方 → 适用系统 → 下载来源 → 安装与启动 → 常见障碍。
- 问题型：直接给答案 → 条件/例外 → 具体操作 → 必要FAQ。
- 比较型：先给差异最关键的一句话 → 按相同维度比较 → 选择建议 → 获取路径（如果相关）。

搜索意图是优先级；不必为读者讲冗长的行业背景。详见 seo-writing.md。

## 类型四：福利活动

- 领取型：福利事实（已核实） → 适用与不适用人群 → 领取步骤 → 到账核验 → 有效期与限制 → 入口。
- 体验型：真实领取结果（若提供） → 复现步骤 → 资格分支 → 实际权益和使用例子 → 到账/期限提示。
- 问答型：直接说明是否能领 → 当前依据与适用范围 → 操作/核验。不能核实就提供检查方法，不编领取路径。

链接可以靠近第一处明确获取需求的位置，也可以放结尾；关键限制与披露必须邻近相关主张。避免制造倒计时或错过焦虑。

## 类型五：知乎观点型

- 立场型：直接回答问题 → 一个具体矛盾 → 解释理由 → 可执行建议。
- 纠偏型：指出常见误解 → 说明在什么条件下成立/不成立 → 例子 → 回到原问题。
- 经验型：真实个人经历 → 对问题的理解 → 适用条件与局限。没有经历就用论证，不硬写第一人称故事。

知乎问题通常已有标题，默认正文即可；用户要求带标题则带。不要为了结尾推广而答非所问。短回答可以只用2–5段；深入分析按论证需要展开。百度知道偏直接答案和操作说明。

## 类型六：实用教程

- 任务型：目标产物 → 必要材料/前提 → 步骤 → 核验结果 → 常见失败。
- 提示词型：一个具体场景 → 可复制提示词（输入、任务、输出、限制） → 如何检查与修正 → 实用提醒。
- 排错型：出现什么问题 → 先检查最简单的原因 → 逐步定位 → 何时停止并请人工确认。

操作界面必须以当前版本为准；未确认菜单时写操作目标和查找方法，不编按钮名称。示例提示词不承诺工具一定能执行。敏感文件、覆盖删除、下载执行需用户审阅授权；不要关闭安全防护。

## 组合与改写

例如「千问办公电脑版怎么下载」为SEO主类型，若还问会员则加福利资格与到账核查，不另起一篇广告。热点+软件推荐：只写与工具需求有关的热点事实，然后转向功能与操作。口播以成品/问题开场，压缩背景，指令可放屏幕，口播不逐字念长链接。只要改某段则输出该段；转知乎时先回答问题，转SEO时先满足搜索意图，不能只是换一个标题。

## 结构自检

如果删掉小标题仍读得通，说明叙述顺序合理。若每段都像功能卡片、开头与结尾互相复述，重排。若连续文章都有三大点和相同营销过渡，改变主线。没有合理产品关联就不要植入。
