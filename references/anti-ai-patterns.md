# 表达反模式

独立审稿时判断 **哪一句妨碍理解，哪一条独立信息必须保留**。先删与读者问题无关的资料、废话和重复，再看措辞是否妨碍表达。冒号、破折号、排比、加粗、小标题和列表各有用途。正常书面词和必要的格式可以保留。需要修整时只动有问题的范围。

| 表达表现 | 审稿动作 |
| --- | --- |
| 宏大背景、无依据趋势、夸张宣传、伪金句 | 删掉空话，保留有来源的事实及其适用条件。判断说到材料能支撑的位置。 |
| 为语气硬造对立、机械三项排比、每段同一个句式 | 查每个分句是否有新信息。确有比较或步骤时保留关系。 |
| 复读题目、报幕式开头、书面连接词过密 | 让第一句话交代答案或具体对象。由上段留下的问题接下一段。避免用「最近一直在研究」「今天分享一款神器」填入口。 |
| 功能卡片、排版过匀、装饰性标题或加粗，依赖冒号和破折号推进 | 围绕一个任务重排。列表适合真正的步骤或并列条件。 |
| 观点反复、文末复述、硬提炼时代意义或励志收尾 | 删除重复段落，停在最后一个有效事实、动作或判断。 |
| 口语词、感叹句、第一人称过多；亲测、收入或经历无来处 | 先保留真实的作者用词和立场。核实经历，不能确认就删掉该主张或改为明确的假设。 |

## 语义复核

把改稿和原稿对照，逐项核查谁做、何时做、做到了哪一步、在什么条件下成立，以及谁提出这个说法。保留数量、否定、比较范围、保留意见和因果方向。计划、可能与已完成的含义各自保留。原文中的代码、指令、URL、数据、标题与结构默认按编辑范围保护。发现疑似事实错误时单独指出，不用推测改写。

原创校准。原稿「根据项目日志，试点计划下周从一个门店开始。只有一台终端接入。」可顺成「项目日志里写的是下周先在一家门店试点，目前只接入了一台终端。」需要保留消息来源、计划状态及当前数量。

最后把稿件当成一篇正常中文文章读一遍。一个了解资料的普通博主，会不会自然地这样写？语义、节奏和阅读体验优先，成稿不附规则命中或自评分。
