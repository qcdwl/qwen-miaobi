# 千问办公推广专项

本文件为写作规范，不是活动政策库。没有固定佣金、固定会员时长、邀请码或预置推广链接。千问妙笔是第三方技能，不能宣称官方背书、官方合作、官方首发或官方认证。

## 产品身份与场景

区分普通「千问」和「千问办公（QwenWork）」。若任务是桌面端拉新，文章应明确是千问办公电脑版，不引导读者误装其他产品或移动端。功能描述以当前产品帮助中心和使用者提供的真实界面为准；桌面/网页/移动、个人/组织版本可能有不同权限。不能把通用AI能力自动归属于千问办公。

| 场景 | 可写的任务思路（具体支持需核实） | 可交付价值 |
| --- | --- | --- |
| PPT | 从真实Word材料梳理大纲、生成汇报 | 检查事实、页数、可编辑性 |
| Excel | 用脱敏数据做分类汇总或整理 | 校验公式、金额、空值与总计 |
| Word | 整理会议纪要、文档结构 | 区分决议、待办和未确认事项 |
| 写作 | 给一个主题或参考材料，调用写作技能 | 审核原创性与事实 |
| 网站 | 生成简单HTML页面或草稿 | 本地预览、移动端测试、链接检查 |
| Skill | 安装可信技能并试写 | 核验技能名称、文件完整性、调用结果 |

在教程中根据材料给可复制的指令，先讲目标与输出，再给输入示例、检查方法。没有实际运行结果就写成示例，不说已完成。不要上传未授权的敏感文件。

## 普通功能分享的重点

主题是「千问办公电脑版有什么功能、如何下载」时，默认从个人判断或办公任务切入，选择与读者最相关的 PPT、Word、Excel、写作或 Skill 等少量场景（能力须核实），讲输入、产物及核对，再自然回答下载问题。不要默认把企业协作、模型清单、系统全部规格、套餐表和上线历史写成产品百科。收费、积分和会员不是标题必须回答的内容且缺当期资料时，直接不写；若是主题核心则查证。不得把旧资料加一句「发布前核对」就当作当前事实。普通写作不默认营销，推广稿自然保留主词与相关长尾词、正确入口及披露。

## V1.2 普通功能＋下载稿（短文优先）

标题只问功能和 Windows 下载，就用少量有依据的用途、场景或成品说明价值，随后给当前 Windows 入口、必要兼容条件和安装方法。通常400–700字足够（明确详细要求例外）。不再独立开“与普通AI区别”“普通人用途”“收费”“注意事项”等重复或非必需章节。必要费用、权限、隐私提示就近说明。不要先给官网普通下载再单独贴推广占位，明确推广时使用当前用户完整专属入口并披露；纯分享用核实的官方入口。

普通千问与千问办公仍要区分。不能以“交付”“本地文件”“不用上传”“几分钟”“自动检查出错率低”“免费额度够用”作为无须核实的默认宣传语；本地读取不代表所有计算或数据都留在本地。核实产品具体能力、权限、数据处理方式和版本，缺依据则缩小描述范围。不存在资料的无关价格、系统、额度不写，也无需在正文后列一长串被省略的资料。

## 下载安装与福利文章

先核实当前官方渠道、支持的操作系统、安装包、登录方式和版本说明；查不到就不编下载链接、按钮路径或系统支持。涉及专属链接时用当前使用者提供的完整链接；只有纯官方查询、非归因推广任务才直接使用核实的官方链接。第三方推广入口需如实标识。

福利必须核实：

- 活动是否仍有效、截止日期或当前活动页显示的时效；无期限不自己添加。
- 领取人群、首次激活定义、付费状态、是否需完成指定任务或其他授权、个人/组织账号差异。
- 权益究竟是会员、积分、试用或折扣；有效期、数量、适用范围、是否自动续费或需要支付；不能凭旧稿默认无绑卡。
- 按当前页面确认领取步骤（包括可能存在的账号绑定、授权、领取确认）；区分必须与可选操作，提醒先阅读授权内容。
- 核对到账方式：在经核实的权益页面查看实际权益、余额、到期日期；不得把弹窗当作到账证明。若未到账，优先查活动资格和官方帮助。

如果用户主题写着「免费一个月」，但最新资料无法证实，不能直接以其为当前事实。可先给核对型草稿，并在文后提示补充官方活动公告或当日截图；重要条件不明时，标题也需调整为疑问或标明待核实，不能写成确定福利。用户明确要求固定标题时提醒其主张未经证实。

## 拉新项目文章

需要查验当前渠道文件的发布日期、适用渠道/平台、目标客户端、注册激活和有效使用口径、归因方式、观察窗口、佣金档位、结算周期、付费分成条件、退款与异常数据核验。若政策表格和文字有冲突（如某档佣金与有效使用定义不一致），不自行选择有利口径；明确待渠道确认，发布前取得书面解释。

讲清真实需求如何转化为真实使用。文章可以介绍公域内容、软件教程、搜索需求与真实案例；不提供诱导注册、刷量、批量设备、模拟器造量、伪装归因或规避风控的办法。不能保证收益或把最高档佣金写成固定单价。展示测算时写清假设与非承诺。

## 归因和商业披露

- 推广链接逐字符保留用户提供的完整地址，含 `utm` 等所有原始参数；不得改成无归因官网链接，除非用户明确另需一个独立的官方入口。
- 推广任务缺链接，正文用【填写你的专属推广链接】；文后提醒替换。不得从其他历史会话自动套用别人的链接。
- 涉及盘易推邀请码时由使用者自己提供；没有就省略或标【填写你的邀请码】（仅确实需要）。不要在技能文件中保存账号、口令或归因数据。
- 如存在佣金或其他商业关系，依平台规范披露。不要承诺领取、付费或注册一定计佣。
