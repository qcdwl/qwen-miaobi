# 文章结构与选题

把「是什么、为什么、怎么做」当成对内容的三句提问。先判断读者此时为什么要看、最关心哪条信息。只回答对应问题，去掉与题目关系弱的素材。能用两段答完就用两段，层级由信息决定。

| 写作任务 | 优先给读者的信息 |
| --- | --- |
| 获取资源或安装软件 | 正确的入口、适用系统与必要步骤。题目同时问功能，才交代能帮助选择的用途。 |
| 软件分享与产品体验 | 从可信成品、读者的场景或实际选择切入。说清输入、动作、产物或取舍。官方演示、作者实测与假设用途分别归因。 |
| 知乎观点与副业选择 | 直接答。给出判断依据、适用条件和能验证判断的小动作。无资料时避免市场趋势和收入断言。 |
| AI 使用教程与排错 | 交代前提、操作或可复制提示词、核对方式。例子涉及上传资料时交代授权。界面未核实就描述操作目标。 |
| 项目科普与复盘 | 科普讲清需求、制作和收费机制，再介绍适用工具。复盘围绕作者实际选择、遇到的卡点、调整与已知结果。 |
| 软件落地页 | 展示用途或真实产物，给获取方式、费用和必要依赖。 |
| 热点或行业观察 | 核实事件、时间及指标。由读者需要解释的变化连接主题。榜单无法查证时，可交付明确标注的长期选题。 |

明确文章的主问题。读者看完应能理解一件事、做一个选择或完成一个动作。开头先给方向，之后的信息顺序由读者还需要知道什么决定。能用一个场景解释清楚时，省掉并列案例。教程的顺序沿实际操作，对比按同一维度组织，分析先给判断，再给能支撑它的事实与理由。

给观点核对一次推理。说清哪条证据支持哪一步，事实、推断和建议各有来由。证据仅覆盖某种情形时，在观点旁说清适用条件。有重要反例或别的解释才纳入。用能被读者验证的操作和结果解释术语，必要的数字写明口径。

科技选题先找「哪个读者会用上」「手里的材料能说明什么」「此刻有什么新变化」。有变化就追到原始来源。没有时效性也可以从高频问题展开。素材先按用途挑选，优先让读者看到一项可复现的操作或可判断的结果。

开头可直答、给一个具体任务、展示实际产物或给有依据的观点。使用真实对比时核查同版本同条件，保留影响选择的差别。结尾可停在最后一个动作或判断。工具星标、播放量和社会热度分别使用各自的口径。
