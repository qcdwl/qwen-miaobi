# 编辑删减

看段落完成了什么，再看用词。

1. 给每段找一项读者会失去的信息，如理由、事实、步骤或条件。逐段删掉可由前文推出的内容。同一个功能在用途、场景、结尾出现三次，就留最清楚的一处。
2. 若段落都在回答「它还支持什么」，拿掉功能标签，围绕读者要完成的事情重排。正文可以按材料、操作和产物走，也可以先把入口给找下载的人。必要的限制放回需要它的那一步。
3. 核对句子有没有凭空拉高可信度或情绪。删自造的效率数字、夸张比喻、编出的习惯和实测。表达观点时留理由，频繁的「我觉得」本身没有信息量。
4. 对照看得到的近稿，分别问开头在做什么、读者遇到的例子是什么、正文靠什么推进、入口为何在这里、末段交付了什么。语义和结构相同就重新取舍。没有前稿时只检查本稿。

例如「本地文件。支持读取……」「表格。支持汇总……」「普通人可以用它整理表格……」可以合并成一件事：「如果要按月份统计订单，把有权限使用的明细交给支持表格处理的工具，按月汇总后和原表核对总额。」能力仍需核实。改写后读者知道输入和检查方法，重复功能段可以删除。

「它不是一个聊天框」「最大的区别是交付」「第一次先拿个不重要的文件试试」有时适用，判断依据是它能否推进眼前这篇。删掉为显口语加入的俚语、刻意错字、文章末尾的助手邀约和复述。结尾可以直接停在最后一个有用的动作或判断。
