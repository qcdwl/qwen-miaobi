# SEO 写作

动笔前提取一个核心词、少量真正相关的长尾意图，以及读者要拿到的答案。核心词自然进入标题和正文。标题以读者正在找的答案来表述，直接写清产品、系统或问题，避免刻意悬念。标题已指定时保留其约束。长尾有实际答复才使用。按需用能跳读的小标题、描述性链接和必要 FAQ。摘要、slug、meta description 等元数据在用户要求时提供。关键词密度和搜索量均无需猜测。

| 搜索意图 | 正文给到 |
| --- | --- |
| 下载、安装 | 已核实的对应平台入口、必要版本或架构、安装和启动。区分项目源码、正式发行包及第三方渠道。 |
| 功能、用途 | 与该读者有关的少量功能，用输入与产物说明作用。 |
| 教程、排错 | 材料、操作、预期结果及核验。按实际故障查版本、系统、依赖和权限。 |
| 费用、会员 | 当前免费范围、资格、成本、期限及权益核验。 |
| 对比、选择 | 同条件对比与选择理由。 |
| 拉新项目 | 当前有效行为、归因、结算条件和成本。 |

如「千问办公电脑版有什么功能，Windows 系统如何下载」，产品名是主词，Windows 下载是必须回答的动作；制作 PPT 仅在正文确实介绍并核实支持时成为长尾。其他系统、套餐或公司历史只在读者另有需求时写。通用下载题在无明确系统时可按用户需要给经核实的版本分支。

同产品再写下载、功能、会员、对比或教程时，入口、产物、权益、选择理由和操作步骤各有不同的实际信息价值。只有标题不同的批量稿应合并或重做。需要推广时先按营销规范确定正确入口；搜索需求仍决定文章内容。旧福利改正文和标题中的主张，单纯加「以官方为准」不足以纠正。

连续接到相似关键词时，先列每篇必须新增的答案。例如功能篇解释输出能力，下载篇解决包型，实操篇交付指令和核对方式。读者意图和资料相同、没有信息增量的主题可以合成一篇。用户要求分别交付时，保留每篇真正独立的答案。
