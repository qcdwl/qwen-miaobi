# SEO：先解决搜索问题

## 搜索意图

把主题转换成读者此刻要完成的动作，不要只按关键词写一篇泛介绍。

| 搜索词类型 | 真实需求 | 文章重点 |
| --- | --- | --- |
| XX电脑版怎么下载 | 找正确入口、版本 | 官方/第三方身份、系统、下载、安装 |
| XX怎么用/怎么做PPT | 完成一个任务 | 材料、操作、提示词、结果检查 |
| XX免费吗/会员怎么领 | 成本与权益 | 资格、活动时效、免费范围、到账 |
| XX和YY有什么区别 | 作选择 | 同类维度、场景、限制 |
| XX拉新怎么做 | 理解项目与有效规则 | 归因、有效使用、结算与风险 |
| XX打不开 | 解决失败 | 版本、系统、依赖、权限、官方排错 |

不为无关词制造流量入口。读者找官方软件，就不要把第三方客户端冒充官方。没有可信信息支持时不要用「最新版」「官方」「永久免费」「全平台支持」等断言。

## 标题与关键词

标题自然包含主要关键词和一个具体承诺，例如「XX电脑版怎么下载？Windows安装与启动方法」。正文开头尽早给直接答案；后续自然出现相关长尾词（版本、系统、安装、使用等），不要求关键词密度或每段重复。标题已经由用户给定时尽量保留，不擅自改成夸张标题。

- 一篇文章解决一个主搜索意图，必要时关联一两个次意图。
- H2仅用于读者需要跳读的分节；FAQ只写有实际价值的问题。
- 网站可用短段落、清晰标题、描述性链接文字；公众号不必硬写网站元数据。用户要求摘要、slug、meta description 时才额外输出。
- 下载入口靠近操作，不让读者读完长篇背景才找到；先核对域名与目标，区分项目仓库与官方发行包。

## 热点与长尾

热搜提供短期关注，搜索型教程提供长期可用的答案。先确认热点日期、来源与真实需求，然后才匹配工具；工具星标和更新时间不能替代社会热度。若热点过期，去掉「今天刚」「刚刚上线」等措辞，保留长期有用的操作内容。

## 避免低质批量文

同一产品的「怎么下载」「有哪些功能」「和普通版区别」「会员怎么领」必须各自有独立信息，不允许只替换标题、系统名称、段首词或同义词。能读取旧稿时比较核心结论、场景和步骤，重复的公共说明压缩为必要内容，不必每篇完整复制。没有独立内容时建议合并问题；若用户指定分别写，至少按不同搜索意图提供不同答案。

## 来源与更新

联网查证当前官方帮助、下载页和公告。记录事实对应版本或日期；没有确认的入口、UI或功能不要猜。涉及过期福利，应修改正文而不只是加一句「以官方为准」。必要时在文章末尾单独提供简洁来源/待核查清单；平台允许时在关键事实附近引用来源。不把搜索排名、预计阅读量和收益写成保证。
